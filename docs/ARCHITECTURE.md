# Architecture — GhostShell

## 1. Design principle

Keep the first version small and understandable. Use separate modules for user interaction, local model communication, prompt construction, and command execution.

## 2. High-level flow

```text
User
 |
 v
main.py
 |
 +--> terminal.py ----> Display / confirmation / execution
 |
 +--> prompts.py -----> Build ghost instructions and context
 |
 +--> ai.py ----------> Ollama local HTTP API
                           |
                           v
                      Local model
                           |
                           v
                    Generated response
```

## 3. Module responsibilities

### `main.py`
- Starts the application.
- Runs the input loop.
- Routes user requests to the appropriate module.
- Handles exit commands and basic errors.

### `terminal.py`
- Reads commands from the user.
- Displays formatted output.
- Applies deterministic safety checks.
- Requests confirmation before execution.
- Executes only the command entered by the user, never a command generated by the model.

### `prompts.py`
- Stores the ghost persona.
- Builds prompts from the user's command and selected mode.
- Instructs the model to keep responses concise and not invent command results.

### `ai.py`
- Sends requests to the local Ollama API.
- Receives and returns model responses.
- Handles connection errors and timeouts.
- Allows the model name to be configured.

## 4. Request flow

1. The user enters a command.
2. GhostShell classifies the request mode (commentary or explanation).
3. Deterministic checks identify known risky command patterns.
4. The command and limited context are passed to the local model.
5. The model returns commentary.
6. GhostShell displays the response.
7. The user chooses whether to execute the original command.
8. If confirmed, the terminal module executes that original command.

## 5. Local model connection

The initial implementation uses Ollama's local HTTP API, normally available at:

```text
http://localhost:11434
```

The model name should be configurable rather than hardcoded throughout the application. The initial model is `qwen2.5:3b`.

## 6. Failure handling

- If Ollama is unavailable, show a clear message and do not pretend AI analysis occurred.
- If the model request times out, allow the user to retry or continue without commentary.
- If the user declines execution, return to the prompt.
- If a command is flagged as risky, require an additional explicit confirmation or block it according to the safety policy.

## 7. Future extensions

- Add support for other shells.
- Add configurable ghost personalities.
- Add optional local command history.
- Add a local configuration file for model selection and behavior.
- Add tests for command parsing and safety checks.
